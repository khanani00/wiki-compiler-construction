Unified Grammar Reference

A single grammar used consistently across all COS341 supplementary articles — so you never have to re-learn the rules when moving between chapters.

Why a unified grammar?

The Mogensen textbook uses different, sometimes incompatible, example grammars across chapters. This forces you to mentally re-map the rules every time you move from syntax analysis to type checking to code generation. Every worked example in these supplementary articles uses this single grammar instead, so the only thing that changes between chapters is the phase being studied — not the language being compiled.

The Grammar

Program Structure

PROGRAM → main ( GLOBVARS ) ALGORITHM FUNCTIONS

Variables and Types

GLOBVARS → VARS
VARS → ε (empty — no variables)
VARS → VAR , VARS
VAR → VTYPE VNAME
VTYPE → text
VTYPE → number
VNAME → _vname (any valid variable name)
FNAME → _fname (any valid function name)

Algorithm (Statement Block)

ALGORITHM → { STAT }

Statements

STAT → STAT ; STAT (sequence)
STAT → VNAME := EXPR (assignment)
STAT → if COND then ALGORITHM (if, no else)
STAT → if COND then ALGORITHM else ALGORITHM (if-else)
STAT → while COND do ALGORITHM
STAT → repeat ALGORITHM until COND
STAT → return EXPR

Conditions

COND → ( EXPR RELOP EXPR )
RELOP → < > = <= >= (one of these)

Expressions

EXPR → _number (numeric literal)
EXPR → _text (text literal)
EXPR → VNAME (variable reference)
EXPR → UNOP EXPR (unary operation)
EXPR → EXPR BINOP EXPR (binary operation)
EXPR → FNAME ( VARS ) (function call)

Operators extensible

UNOP → add unary operators here as needed (e.g. not, -)
BINOP → add binary operators here as needed (e.g. +, -, and, or)

Functions

FUNCTIONS → ε (no additional functions)
FUNCTIONS → DECL FUNCTIONS
DECL → HEADER BODY
HEADER → FNAME ( VARS )
BODY → ALGORITHM

A Complete Program in This Grammar

The following program is fully valid under the unified grammar. It declares a global variable, defines a helper function, and calls it from main.

/* PROGRAM: main with one global variable and one function */

main ( number x ) {
  number result := 0;
  result := double(x);
  return result
}

/* FUNCTIONS */
double ( number n ) {
  return n + n
}

How This Grammar Is Used Across Chapters

Chapter 3

Scopes & Symbol Tables

The ALGORITHM rule defines a scope boundary. Every { STAT } block triggers an enter() call in the symbol table. VAR declarations are bound using bind(). VNAME references are resolved using lookup().

Chapter 5

Type Checking

VTYPE provides the declared type for vtable entries. EXPR rules map directly to cases in CheckExp. HEADER provides function signatures for ftable. BODY is what CheckFun type-checks against the declared return type.

Chapter 6+

Code Generation

STAT rules map to intermediate code instructions. ALGORITHM blocks define the structure of code blocks. DECL drives function prologues and epilogues. The same grammar, the same example programs — only the output changes.
