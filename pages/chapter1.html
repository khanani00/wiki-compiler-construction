Chapter 1 — Lexical Analysis

“The pattern defines the boundary; longest match decides where one token ends and the next begins.”

Opening Problem

Here is a fragment from the gcd program:

temp := b;
b := a - (a / b * b);
a := temp

To you, these 3 statements are immediately clear.

To a compiler, this is a source file — a stream of characters.

Before the parser can build any structure, something has to scan these raw characters and group them into tokens: identifiers, operators, numbers, keywords and so on.

This something is the lexer.

Why do we need a lexer?

A compiler's job is to turn source code into something a machine can run. That happens in stages — lexical analysis, syntax analysis, type checking, code generation — and lexical analysis is the first one, because every later stage needs to work with meaningful tokens (identifiers, numbers, operators), not raw characters.

A lexer groups characters into tokens, discards what doesn't matter (whitespace, comments), and hands the parser a clean, categorised stream to work with.

Learning Objectives

By the end of this article you should be able to:

  • Remember the token types in the Reference Grammar (keyword, identifier, number, assign, relational operator, binary operator, symbols) and the three lexer rules: longest match, priority and error handling.
  • Understand why a regular expression cannot be executed directly, and explain how the regex → NFA → DFA path turns a pattern into a working scanner.
  • Understand the difference between an NFA and a DFA (ε-transitions, multiple transitions per symbol), and explain why lexers are built on DFAs.
  • Apply ε-closure and subset construction to convert a small NFA into a DFA.
  • Apply the DFA minimisation algorithm to the combined DFA, grouping accepting states by token class.
  • Analyse a scan trace to determine where each token ends, showing how longest match, priority and lexical errors decide the outcome.

Connecting to What You Already Know

You should already be comfortable with regular expressions or pattern matching before this chapter. Everything here turns that familiar idea — a compact description of a pattern — into a program that scans character by character.

Why a DFA?

A regular expression describes a pattern but gives no procedure for matching it. An NFA is a mechanical translation of the regex, but it may have several choices per character, so running it means backtracking or tracking many states at once. A DFA has exactly one move per state and character, so the scanner reads each character once, with no backtracking. That is why we convert regex → NFA → DFA.

Rules to remember

Longest match: always consume the longest valid prefix, not the first thing that happens to match.

Priority: when two token types could both match the same longest string (a keyword like number also matches the Identifier pattern), keywords get first preference.

Error: if no transition exists from the current state and no accepting state has been passed through since the token began, the lexer cannot form a valid token — this is reported as a lexical error at that position.

Creating the DFA

Turning a pattern into something a lexer can actually run takes four stages: regex to NFA, NFA to DFA, combining every token type's DFA into one, then minimising the result.

Step 1 — Regex to NFA

The NFA represents all valid patterns that can belong to that token group. An NFA can contain epsilon (ε) transitions, which allow the automaton to move from one state to another without reading an input character. An NFA may also allow more than one possible transition from a state. The final accepting states represent valid matches for the token.

Step 2 — NFA to DFA

The NFA is converted into a DFA using epsilon-closure and subset construction.

The epsilon-closure of a state is the set containing that state and all other states that can be reached using only epsilon (ε) transitions. This can be understood by asking: “Where can I reach without reading another character?”

A DFA contains no epsilon transitions. For each input symbol, the DFA has only one possible transition from a particular state. Each DFA state is a set of NFA states.

State B is {1, 2} because state 1 reaches state 2 without reading a character. That ε-closure is the only real work here.

The start state is the ε-closure of {0}, which is {0, 1, 3}. For each character class, take move and then the ε-closure of the result. Split [0-9] into 0 and [1-9], because the two branches treat them differently.

Worked step: from A on [1-9], move gives {4}, and its ε-closure is {4, 5, 6, 8, 9}, which is C. From C on any digit, move gives {7}, and its ε-closure {6, 7, 8, 9} is D. D loops to itself. B, C and D accept because their sets contain NFA state 9.

C and D behave identically but have different NFA sets, so subset construction keeps them apart. Minimisation will merge them later.

Letters are the exception

Keywords and identifiers both start with a letter, and every keyword is also a valid identifier. So the two machines are overlaid, not just merged:

  • Every keyword-prefix state (i, wh, retur, …) also accepts Identifier.
  • Any character that does not continue the keyword leads to the Identifier loop state.
  • The last state of each keyword accepts both KEYWORD and Identifier. The priority rule picks KEYWORD. A further letter moves it on to Identifier, so ifx is an identifier.

Nothing has been minimised yet, so the combined DFA still has every redundant state from Step 2: 52 states (S0, 2 for ASSIGN, 3 for NUMBER, 2 for RELOP, 3 for BINOP, 6 for SYMBOL, 2 for Identifier, and 33 for the keywords).

Step 4 — Minimise the combined DFA

Why minimise, and why now?

DFAs built from regular expressions through NFAs are often non-minimal. Any regular language has a unique equivalent minimal DFA, so minimising is well-defined and gives the smallest possible machine.

DFA Minimisation

Two states are equivalent if they cannot be distinguished by any sequence of input symbols. We identify equivalent states using two rules:

  • An accepting state is never equivalent to a non-accepting state.
  • If states s1 and s2 transition on the same symbol c to states t1 and t2 that are already proven different — or if only one of s1, s2 has a defined transition on c — then s1 and s2 are different.

Rather than testing all pairs directly, the algorithm works by grouping states and splitting groups when inconsistency is found:

  1. Start with unmarked groups.
  2. Pick any unmarked group G and check if it is consistent: for every pair of states s1, s2 in G and every symbol c, move(s1, c) and move(s2, c) must both land in the same group, or both be undefined. If G is consistent, mark it. If not, split G into maximal consistent subgroups, replace G with those subgroups, and erase all marks.
  3. If no unmarked groups remain, stop — the current groups are the states of the minimal DFA. Otherwise return to step 2.

Useful shortcut

A group of exactly one state is trivially consistent and never needs to be split, so the algorithm can stop as soon as all unmarked groups are singletons.

A lexer-specific twist

Mogensen starts with accepting versus non-accepting. In a lexer, accepting states are grouped by the token class they emit. Two accepting states for different tokens are never equivalent. The lexeme text still records which character or keyword actually matched.

Round 1. Check each group for consistency:

  • non-accepting: S0 has many transitions, ASSIGN state 1 has only =. Split.
  • NUMBER: the zero state has no exits, the other two loop on digits. Split into {zero} and {first digit, digit loop}.
  • ASSIGN, RELOP, BINOP, SYMBOL: no outgoing transitions, so they are consistent. Mark them.
  • KEYWORD: all 8 states go to the Identifier group on a letter, digit or underscore, so it is consistent.
  • Identifier: eight of the 27 states have a transition into the KEYWORD group, and the letter differs. Split them by letter: on n {mai, the, retur}, on e {els, whil}, on f {i}, on o {d}, on r {numbe}. The other 19 states stay together for now.

Rounds 2 to 5. Each round peels one more step back along the keyword chains. For example, ma goes to the {mai, …} group on i, while el goes to the {els, whil} group on s, so they now differ. Because number and return are the longest chains (5 prefix states), this stops after about five rounds. Every state that continues on a different letter ends up alone.

With the minimised combined DFA, the lexer is complete: a single deterministic automaton that recognises any token in the language, one character at a time, with no backtracking.

Scan trace

scan() drives it: start at S0, follow transitions while they exist, remember the last accepting state passed, and when no transition exists, emit the token for that state and reset to S0. If no accepting state was passed since the token began, report a lexical error.

Key Takeaway from the Trace

            

                Every step follows the same two rules: consume characters while a transition exists,
                and only accept once none does (longest match);
                when a string could be more than one token type,

                    start at S0, follow a transition if one exists,
                    remember the last accepting state you passed through,
                    emit a token and reset to S0 once none exists.

Exercises


        

            
Apply Exercise 1.1

            
Given the regex [ab]*c, construct the NFA, then apply subset construction to get the DFA.

            

                Show answer
                

                    Using Thompson's construction: build an NFA for a, one for b, combine
                    them with a union (a|b), apply the Kleene-star construction to get
                    (a|b)*, then concatenate an NFA for c onto the end. The result has a
                    single accepting state, reached only after zero or more a/b
                    characters followed by exactly one c.
                

                

                    Applying subset construction: the start state's ε-closure includes every state
                    reachable before consuming input. On each a or b, the closure stays
                    within the “looping” part of the machine, so a single DFA state can represent this entire
                    loop. On c, that DFA state transitions to a new, accepting DFA state. Any further
                    a, b, or c from the accepting state has no valid
                    continuation of this pattern, so there is no transition (or a dead state, if you complete the DFA).
                

            

        


        

            
Analyse Exercise 1.2

            

                A DFA has two states that both transition identiically on every input symbol and lead only to rejection.
                Explain why these can be merged during minimisation,
                and what would go wrong if they were not merged in a large lexer with hundreds of token types.

            

                Show answer
                

                    Two states are equivalent for minimisation if, for every possible remaining input, they either
                    both lead to acceptance or both never do. From the scanner's point of view, they behave
                    identically no matter what comes next, so keeping them separate adds no distinguishing power.
                    Since both states here always lead only to rejection regardless of input, they meet exactly
                    that condition and can be collapsed into one dead state.
                

                

                    If they were not merged, every additional token type introduces its own redundant dead states
                    rather than sharing the DFA's existing ones. In a lexer with hundreds of token types, this
                    multiplies the number of states and the size of the transition table without changing which
                    strings are recognised — it costs memory and lookup time for no benefit.
                

            

        


        

            
Create Exercise 1.3

            

                Following the same pipeline used above, construct the minimised
                DFA for the NUMBER token (0 | [1-9][0-9]*) and for the semicolon symbol.
                Compare their sizes — why is the semicolon's so much smaller?
            

            

                Show answer
                

                    The minimal NUMBER DFA has 3 states: a start state, a “zero” accepting state with no exits
                    (so 05 scans as 0 then 5), and a “digits” accepting state
                    reached on [1-9] that loops on [0-9].
                

                

                    The semicolon is the simplest possible case: a single-character token. Its minimised DFA has
                    exactly two states — a start state and an accepting state reached on ;, with no
                    loop, since nothing can extend a valid semicolon token further. That is why it is smaller:
                    there is nothing to repeat.
