Overview

This supplementary material keeps the language, grammar and examples consistent across every chapter so you only learn one compiler while exploring each compiler phase. As you progress through the chapters, you will watch this single program evolve from raw characters into a fully compiled program.

One Grammar. One Program. One Compiler. 

main(number a, number b) {
  number result := 0;
  result := gcd(a, b);
  return result
}

gcd(number a, number b) {
  number temp := 0;
  while (b > 0) do {
    temp := b;
    b := a - (a / b * b);
    a := temp
  };
  return a
}

isZero(number x) {
  number out := 0;
  if (x = 0) then {
    out := 1
  } else {
    out := 0
  };
  return out
}

This is the only program we are working with throughout. Every compiler phase studies this same program from a different perspective. Follow the Reference Grammar for the full language definition.

Code blocks: program vs. pseudocode

Two kinds of code appear throughout the site, styled differently so you can always tell which is which instantly.

Program (example code)

main() {
        number x := 5;
        text   y := "hello";
        number z := x + y;   /* adding a number to text — should this work? */
        }

This dark block always refers to the one running program that every chapter studies from a different angle.

Pseudocode (example code)

function TYPECHECK(expr):
        if expr is BINOP(op, left, right):
            t1 := TYPECHECK(left)
            t2 := TYPECHECK(right)
            if t1 != t2:
                report type error
            return t1
        return TYPE_OF(expr)

This lighter block means pseudocode, which an algorithm that acts on the program (like a type-checking routine), rather than being the program itself.
