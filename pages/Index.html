Overview

This supplementary material keeps the language, grammar and examples consistent across every chapter so you only learn one compiler while exploring each compiler phase. Instead of introducing a different language in every chapter, every example throughout this website uses the same grammar and the same running example. As you progress through the chapters, you will watch this single program evolve from raw characters into a fully compiled program.

One Grammar. One Program. One Compiler. 

main() {
  number x := 5;
  text   y := "hello";
  number z := x + y;   /* adding a number to text — should this work? */
}

This is the only program we are working with throughout. Every compiler phase studies this same program from a different perspective.

Follow the Reference Grammar for the full language definition.

Manual: how to read this site

Code blocks: program vs. pseudocode

Two kinds of code appear throughout the site, styled differently so you can always tell which is which instantly.

The Program

main() {
        number x := 5;
        text   y := "hello";
        number z := x + y;   /* adding a number to text — should this work? */
        }

This dark block always means the one running program that every chapter studies from a different angle.

Pseudocode

function TYPECHECK(expr):
        if expr is BINOP(op, left, right):
            t1 := TYPECHECK(left)
            t2 := TYPECHECK(right)
            if t1 != t2:
                report type error
            return t1
        return TYPE_OF(expr)

This lighter block means pseudocode, which an algorithm that acts on the program (like a type-checking routine), rather than being the program itself.
