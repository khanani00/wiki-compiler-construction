Chapter 2 — Syntax Analysis

Building a parser that deterministically knows which rule to apply next.

LL(1) Parsing — Applied to the Referenced Grammar

We apply the full LL(1) analysis to a subset of the referenced grammar — the parts covering variable declarations, statements, and the program structure. This is where the nullable production lives and where the interesting decisions happen.

Step 5 — LL(1) Conflict Check

A grammar is LL(1) if and only if no cell contains more than one production. Every cell above has at most one entry — this grammar subset is LL(1).

The interesting case: VARS

VARS has two productions: VARS → ε and VARS → VAR , VARS. FIRST of the non-empty production = {number, text}. The nullable production applies only when t ∈ FOLLOW(VARS) = {)}. The sets {number, text} and {)} are disjoint → no conflict.

What a Conflict Looks Like — Dangling Else

If we allowed both:

STAT → if COND then ALGORITHM
STAT → if COND then ALGORITHM else ALGORITHM

Both have FIRST = {if}. The parse table would have two productions in the same cell for STAT under token if — a conflict. The fix is left-factoring:

STAT      → if COND then ALGORITHM ELSE-PART
ELSE-PART → else ALGORITHM
ELSE-PART → ε

Now STAT has one production for if. ELSE-PART chooses else ALGORITHM (Rule 1) or ε when the lookahead is in FOLLOW(ELSE-PART) (Rule 2). No conflict.
